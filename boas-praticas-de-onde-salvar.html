Seção 03

Rotina de Organização — 20 a 30 min por dia

Consistência bate perfeição
Tempo total
20–30 min
Feito todo dia, esse ritual elimina acúmulo, garante que o time encontra o que precisa e mantém o repositório como fonte confiável da verdade.
01
5 min · Abertura
Revisar o que ficou pendente ontem
Antes de começar qualquer tarefa nova, olhe o que ficou pela metade. Arquivo aberto, mensagem não salva, processo escrito no bloco de notas.
Abra o Git e rode git status para ver o que está modificado mas não commitado
Verifique sua área de trabalho e Downloads — mova ou descarte o que estiver perdido
Se tiver rascunho de texto útil em qualquer lugar: coloque no lugar certo agora
02
5 min · Git
Salvar o que foi produzido no dia anterior
Qualquer texto, processo, script ou decisão que foi escrita ontem e não foi commitada — faz agora.
Identifique os arquivos modificados com git status
Faça staging apenas dos arquivos relevantes — nunca git add .
Commit com mensagem descritiva: o que mudou e por quê
Push para o repositório remoto
03
5 min · Drive
Arquivos pesados e documentos do dia
PDFs, contratos, NFs, vídeos, imagens que chegaram ontem vão para o Drive agora — não deixe acumular.
NF recebida → 01_BACKOFFICE/Financeiro/Notas-Fiscais/
Criativo aprovado → 02_MARKETING/Criativos/{produto}/
Gravação de aula → 04_ENTREGA/Produtos/{produto}/Aulas/
Contrato assinado → 01_BACKOFFICE/Contratos/{categoria}/
04
5–10 min · Refinamento
Atualizar um processo ou documento importante
Escolha uma coisa que ficou desatualizada — preço, SOP, script, offerbook — e corrija. Apenas uma. Pequeno e consistente ganha de grande e esporádico.
Releia um processo que você usou recentemente — está correto e atual?
Se houver divergência entre o que está escrito e o que é praticado, corrija agora
Commite a atualização com a data no commit: feat(processos): atualiza script SDR FPH — abr/26
05
5 min · Fechamento
Deixar o ambiente limpo para amanhã
O objetivo é terminar o dia com o repositório sincronizado e sem arquivo "solto" esperando ser categorizado.
Último git status — se houver algo modificado, commite ou descarte
Feche abas de arquivos que não precisam mais estar abertas
Se descobriu que falta uma pasta ou padrão: anote para propor ao Michael
Nenhum arquivo no Desktop ou Downloads que deveria estar no Drive ou no Git
→
O repositório só é confiável se estiver vivo. Um arquivo que existe só no computador de uma pessoa não existe para a equipe. Cada commit é um ato de generosidade com quem vem depois.
