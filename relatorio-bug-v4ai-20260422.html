Resumo executivo

Em 22/04/2026, uma deal que estava no funil Closer (etapa "Reunião Agendada", stage_id 112) foi movida automaticamente para o funil SDR-Novo (etapas "Conectado IA" → "MQL") sem nenhuma ação humana. O processo de venda foi interrompido e a correção manual foi feita às 14:58 UTC pela Rafaela.

A investigação identificou que a causa foi um workflow no n8n da V4AI/Collie Associados que escuta eventos de mudança de deal no Pipedrive e move deals para a etapa "Conectado IA" (stage 481) sem verificar se a deal já avançou para um funil posterior (Closer).

Este documento descreve o incidente em detalhes e especifica exatamente o que precisa ser ajustado nos workflows da V4AI para que o problema não se repita.

Contexto — Estrutura de Funis OMNI Brasil

O Pipedrive da OMNI Brasil possui dois funis principais. Um lead percorre o funil SDR primeiro e, quando avança para reunião, é movido para o funil Closer. São fluxos sequenciais, e o funil Closer representa uma etapa mais avançada da venda.

Funil Pipeline ID Etapas Descrição
SDR-Novo 65 480 → 481 → 420 → 421 → 422 → 423 → 485 Prospecção inicial, qualificação e conexão
Closer 21 112 → 113 → 116 → 114 → 280 Reunião agendada → venda
Regra crítica: quando uma deal chega ao funil Closer (pipeline_id = 21), ela não deve ser movida de volta para nenhum stage do funil SDR (pipeline_id = 65). Qualquer operação que altere o stage_id de uma deal deve verificar primeiro o pipeline_id atual.

Causa raiz

Webhook "Estagio Deal" sem verificação de pipeline

O webhook Pipedrive ID 2959184 ("Webhook Estagio Deal"), registrado na conta da OMNI Brasil sob o usuário Rafaela (ID 2872886), escuta o evento deal.change de forma irrestrita — ou seja, qualquer mudança em qualquer deal, independente do funil onde ela está.

Quando a deal chegou ao funil Closer (stage 112), essa mudança disparou o webhook. O workflow do lado da V4AI/Collie não verificou o pipeline_id atual da deal antes de agir, e moveu a deal de volta para o funil SDR, revertendo o avanço no processo de venda.

O que precisa ser corrigido

Correção 1 — CRÍTICA: Adicionar guard de pipeline no workflow "new-lead-moved-omni"

O workflow que recebe o webhook deal.change (ID 2959184) deve verificar, antes de qualquer ação, se a deal ainda está no funil SDR (pipeline_id = 65). Se a deal já avançou para o funil Closer (pipeline_id = 21) ou qualquer outro funil, o workflow deve encerrar sem executar nada.

Lógica de proteção a adicionar (início do workflow):

// Recebe o payload do webhook Pipedrive
const deal = $json.current;

// GUARD: só processar deals do funil SDR-Novo (pipeline_id = 65)
if (deal.pipeline_id !== 65) {
  throw new Error(`SKIP: deal ${deal.id} está no pipeline ${deal.pipeline_id}, não no SDR (65). Abortando.`);
}

// GUARD adicional: verificar se o stage atual ainda é do funil SDR
const sdrStages = [480, 481, 420, 421, 422, 423, 485];
if (!sdrStages.includes(deal.stage_id)) {
  throw new Error(`SKIP: deal ${deal.id} está no stage ${deal.stage_id} que não pertence ao funil SDR. Abortando.`);
}

// Continua o fluxo normalmente...

Se o workflow usa outro formato de acesso ao payload (ex: $node['Webhook'].json.current ou equivalente no n8n), adaptar a referência conforme necessário. O ponto crítico é o valor de pipeline_id que vem no payload do webhook Pipedrive.

Correção 2 — IMPORTANTE: Adicionar guard de pipeline nos workflows "new-lead-crm-variation"

Os webhooks de deal.create (IDs 2935944 e 2936012) disparam quando qualquer deal é criada. Na OMNI Brasil, deals podem ser criadas diretamente no funil Closer ou em outros funis que não o SDR. Adicionar verificação de pipeline_id === 65 no início desses workflows também evita efeitos colaterais indesejados. 

// GUARD: só processar leads criados no funil SDR-Novo (pipeline_id = 65)
const deal = $json.current;
if (deal.pipeline_id !== 65) {
  throw new Error(`SKIP: deal ${deal.id} criada no pipeline ${deal.pipeline_id}. Não é lead SDR.`);
}

Correção 3 — Opcional: Filtrar por pipeline no webhook do Pipedrive

O Pipedrive permite registrar webhooks com filtros, mas o filtro por pipeline_id não é suportado nativamente na API de webhooks (apenas por user_id). A proteção confiável deve ser feita dentro do workflow n8n, como descrito acima.

  • Deal #280890 (Gisele Mathias) foi regressada do funil Closer para o funil SDR, interrompendo o processo de venda que estava em etapa avançada.
